# V0.3 手机可用版本部署准备

本阶段只准备代码和部署材料，不创建付费资源。真实的 `DASHSCOPE_API_KEY`、`DASHSCOPE_WORKSPACE_ID` 只允许配置在阿里云函数计算服务端环境变量中，不能写入前端、PWA、仓库或浏览器可见配置。

## 第一阶段首选架构

```text
手机浏览器 / PWA
  -> Function Compute 自动 HTTPS 地址
  -> 同一 Web 函数
      /          HTTP 页面与 PWA 静态文件
      /realtime  WSS WebSocket Proxy
  -> 阿里云百炼 Realtime WebSocket
```

当前不要求自定义域名、SSL 证书、ICP备案、容器镜像仓库、ECS、数据库、日志服务或 API 网关。

## 部署方式

首选：

```text
Function Compute Web 函数
Custom Runtime
ZIP 代码包
HTTP Trigger
```

备用：

```text
自定义容器 + 容器镜像仓库
```

备用方案文件仍保留在 `deploy/aliyun-fc/Dockerfile`，但 V0.3 第一阶段不使用。

## 已完成的代码适配

- `server/cloud-server.ts`：生产服务默认监听 `0.0.0.0:9000`。
- `server/cloud-server.ts`：同一个 HTTP Server 同时承载 Next.js 页面和 `/realtime` WebSocket。
- `server/realtime-proxy.ts`：支持挂载到现有 HTTP Server，生产路径为 `/realtime`。
- `lib/config/realtime.ts`：生产环境自动推导 `wss://当前域名/realtime`，本地开发仍用 `ws://127.0.0.1:3001`。
- `package.json`：新增 `npm run start:fc` 和 `npm run package:fc`。
- `next.config.ts`：启用 `output: "standalone"`，减少 ZIP 体积。
- `scripts/package-fc.ps1`：生成可上传的 FC ZIP 包。

## 生产环境变量

必填：

```text
DASHSCOPE_API_KEY
DASHSCOPE_WORKSPACE_ID
DASHSCOPE_REGION=cn-beijing
```

建议：

```text
REALTIME_PROXY_PATH=/realtime
DEBUG_REALTIME=false
ENABLE_TRANSLATION_GLOSSARY=false
```

第一阶段可以先留空：

```text
NEXT_PUBLIC_REALTIME_PROXY_URL
ALLOWED_ORIGINS
```

不填 `NEXT_PUBLIC_REALTIME_PROXY_URL` 时，前端会根据当前 FC HTTPS 地址自动使用：

```text
wss://<FC 公网 Host>/realtime
```

## Function Compute 控制台填写

函数类型：

```text
Web 函数
```

运行环境：

```text
Custom Runtime
```

如果控制台还要求选择语言或模板，选择 `Node.js 20` / Node.js Web 应用模板。

代码包：

```text
deploy/aliyun-fc/ai-translator-fc-v04.zip
```

启动命令：

```bash
npm run start:fc
```

监听端口：

```text
9000
```

HTTP Trigger：

```text
公网访问：开启
认证方式：anonymous / 无需认证
请求方法：GET、POST、OPTIONS
HTTPS：使用 FC 自动提供的公网 HTTPS 地址
WebSocket Upgrade：开启或确认支持
```

## 官方文档依据

- Function Compute Web 函数可用于运行 Web 应用。
- Custom Runtime/Web Server 需要监听 `0.0.0.0:CAPort` 或 `*:CAPort`，不能只监听 `127.0.0.1`。
- Web 函数默认服务端口为 `9000`。
- HTTP Trigger 支持 WebSocket 请求。
- 环境变量在函数配置中注入，不需要进入前端代码。
